# 9. ADR — Архитектурные решения

> Лог ключевых архитектурных решений с обоснованиями.

---

## ADR-001: Feature-Sliced Design (FSD)

**Решение:** Использовать FSD как архитектурную методологию.

**Обоснование:**
- Предсказуемая структура проекта — новый разработчик сразу понимает, где что лежит
- Строгие правила импортов предотвращают спагетти-зависимости
- Хорошо масштабируется при росте проекта
- Активное русскоязычное сообщество (соответствует команде)

**Следствия:**
- Overhead на создание `index.ts` баррелов для каждого слайса
- Необходимость `@x/` паттерна для кросс-entity связей
- Module augmentation для обхода ограничений слоёв (shared ↔ app)

---

## ADR-002: MobX-State-Tree вместо Redux / Zustand

**Решение:** MST как основной стейт-менеджер.

**Обоснование:**
- **Типизированное дерево** — модели с валидацией и типами из коробки
- **Гранулярная реактивность** — критично для 3D (сотни объектов, минимальные ре-рендеры)
- **Патчи и снапшоты** — бесплатный undo/redo через `onPatch` / `applyPatch`
- **Composable models** — миксины `withHistory()`, `withMatrix4()` естественно ложатся на MST
- **DevTools** — подключение к Redux DevTools через middleware

**Альтернативы:**
- Redux Toolkit — больше бойлерплейта, менее гранулярная реактивность
- Zustand — проще, но нет встроенных патчей и типизированного дерева
- Jotai/Recoil — атомарный подход не подходит для сложного иерархического состояния сцены

---

## ADR-003: React Three Fiber вместо императивного Three.js

**Решение:** Использовать R3F для декларативного 3D.

**Обоснование:**
- Декларативный JSX для 3D-объектов — привычный React-подход
- `observer()` из MobX-React-Lite seamlessly интегрируется с R3F-компонентами
- Drei предоставляет готовые абстракции (CameraControls, DragControls, useTexture)
- Автоматическое управление lifecycle Three.js-объектов (dispose, resize)

**Trade-offs:**
- Слой абстракции добавляет overhead (незначительный для данного масштаба)
- Некоторые низкоуровневые оптимизации Three.js сложнее через R3F

## ADR-004: Гибридная стилизация

**Решение:** Tailwind CSS v4 + CSS Modules + SASS Modules + CVA.

**Обоснование:**
- **Tailwind** — быстрая вёрстка, utility-first подход
- **CSS/SASS Modules** — изоляция для сложных компонентов (button с ~290 строками стилей)
- **CVA** — типобезопасные варианты компонентов
- **SASS** — DnD-тематические переменные, вложенность

**Почему не один подход:**
- Чисто Tailwind не подходит для сложных компонентов с десятками состояний
- Чисто CSS Modules — слишком многословно для простых утилитарных стилей
- Гибрид позволяет выбирать инструмент по задаче

## ADR-005: Module Augmentation для FSD-совместимости стора

**Решение:** `IStore` объявлен пустым в `shared`, расширяется через `declare module` в `app`.

**Обоснование:**
- FSD запрещает `shared` импортировать из `app`
- Хуки `useStore()` живут в `shared/lib/mst/hooks.ts`
- Без module augmentation `useStore()` не знал бы тип стора
- Паттерн сохраняет FSD-слои нетронутыми, давая полную типизацию

**Альтернативы:**
- Вынести хуки в `app` — нарушит переиспользуемость
- Generic-параметр — усложнит API хуков
- Ослабить FSD — нежелательно

## ADR-006: TanStack Query с localStorage Persistence

**Решение:** React Query + `query-sync-storage-persister` с 24-часовым TTL.

**Обоснование:**
- Модели и текстуры редко меняются — 24-часовой кэш разумен
- Мгновенное отображение при перезагрузке страницы
- `localStorage` — простой и надёжный persister без IndexedDB-сложности

## ADR-007: Yandex OAuth через NextAuth.js

**Статус:** 🕓 Запланировано — конфигурации NextAuth и провайдера в коде пока нет.

**Решение:** Единственный OAuth-провайдер — Яндекс.

**Обоснование:**
- Целевая аудитория — русскоязычные пользователи
- Яндекс ID — один из самых распространённых аккаунтов в РФ
- NextAuth.js упрощает интеграцию до минимума конфигурации

## ADR-008: Воксельная система на основе Map

**Решение:** Кубы хранятся в `t.map(MCubeMesh)` — MST-мап по ID.

**Обоснование:**
- O(1) доступ по ID — критично для hover/click обработчиков
- MST-мап автоматически отслеживает изменения каждого элемента
- Добавление/удаление кубов — атомарные операции
- Каждый куб — самостоятельный observable → гранулярные ре-рендеры

## ADR-009: Undo/Redo через JSON Patches

**Решение:** Кастомный `withHistory()` миксин на основе MST `onPatch` / `applyPatch`.

**Обоснование:**
- JSON Patches (RFC 6902) — стандартный формат дельт
- MST генерирует патчи автоматически при любом изменении
- Возможность исключать служебные пути (`/sizes/*` — вычисляемые размеры моделей); история подключена только к `construct`, поэтому камера и выделение в неё не попадают
- Компактнее, чем хранить полные снапшоты

**Trade-offs:**
- Сложнее в реализации, чем простой стек снапшотов
- Требует аккуратного управления exclusion-путями
